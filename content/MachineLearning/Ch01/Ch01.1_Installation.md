# 1.1 Install and Use Conda

As an excellent package management tool in Python development, Conda has always had its unique advantages, especially in Machine Learning and Deep Learning development. When we need to distinguish and isolate Python environments with different versions or dependencies, the Conda tool demonstrates its advantages. 

## 1.1.1 Introduction to Conda

Conda is an open-source package management system and environment management system, mainly used for installing and managing Python, its packages, and dependencies. It is a powerful tool for building Machine Learning and data science environments, with the following key advantages:

- Cross-platform: Conda can run on multiple operating systems such as Windows, macOS, and Linux, providing good cross-platform compatibility.
- Environment Management: Conda allows for the convenient creation of independent Python environments, with each environment having its own packages and dependencies, thereby avoiding package conflicts between different projects. 
- Easy to Use: Conda provides a command-line interface, making the management of Python environments intuitive and simple.

In a Python environment, we can install the Conda tool in two ways. The first is to download Anaconda [1] for installation, and the second is to download Miniconda [2] for installation. Anaconda and Miniconda are essentially both Conda-based packages, with Anaconda being an extension of Miniconda. The difference is that the former includes more Python scientific computing packages and is a commercial software, so the installation file is usually larger; Miniconda, on the other hand, is an open-source and lightweight Conda package, and we can install the corresponding Python software according to our actual needs. Since we will need to create our own virtual environment later, we can download the more lightweight Miniconda (the installation process is exactly the same). 

Below are some commonly used Conda commands:

- Create a Python environment named py38 with Python version 3.8 
  ```shell
  conda create -n py38 python=3.8
  ```
  
- Delete the virtual environment named py38
  
  ```shell
  conda env remove -n py38 
  ```
  
- Activate the py38 environment
  ```shell
  conda activate py38
  ```
  
- Exit the current Python environment
  ```shell
  conda deactivate
  ```
  
- List all current Python virtual environments
  ```shell
  conda env list
  ```
  
- Clone the current environment
  ```shell
  conda create -n newpy38 --clone py38 
  ```
  
- Continue to upgrade the Python version in a virtual environment
  ```shell
  1 conda activate py38 # First, activate and enter the virtual environment py38
  2 conda install python==3.9 # Upgrade Python version from 3.8 to 3.9
  ```

## 1.1.4 Book Environment

For any Python environment, it has corresponding dependent packages and their related version dependencies. In a Python environment, we usually export the names and versions of the packages that a project depends on to a fixed file, so that others can reinstall the corresponding environment based on this file. 

**1. Environmental Dependencies**

After entering the Python virtual environment to be exported, we can export it using the following command: 

```Shell
1 pip freeze > requirements.txt
```

After executing the above command, a file named requirements.txt will be generated in the current directory, with contents similar to the following: 

```Shell
numpy           1.26.4
packaging       24.0
pandas          2.2.1
pillow          10.2.0
```

In this file, each line specifies the name of a Python package and its corresponding version number. It should be noted that requirements.txt is just a conventional name and can be any other name. 

Furthermore, we only need to execute the following command to complete the installation process of all Python packages in requirements.txt:

```Shell
pip install -r requirements.txt
```
